Google Drive links in the Lark fault messages

One-time setup, about 5 minutes, done once per Google account. Each bench laptop then needs one link opened once (step 3).

Each fault message in Lark can carry a link that opens that dashcam's folder in Google Drive (70mai Overnight / night_… / <serial>). Google only gives out folder links by their ID, so a small script in your own Google account looks the ID up.

Before you start — both must already be true, or the links stay off with no error:
  • The bench laptop already sends Lark messages: the monitor shows the small green note 📨 Lark alerts armed at the bottom-left. The Drive link only travels inside those messages.
  • In the monitor, Copy results to (or the Save Folder) is Google Drive (G:) → My Drive → 70mai Overnight, and that Drive belongs to the same company Google account you will use below. The script can only find folders that Google Drive for desktop has uploaded there.

1 · Create the script

  1. Open script.google.com, signed in with that company Google account, and click New project.
  2. Click Untitled project at the top-left and rename it 70mai Drive links.
  3. Delete the sample text in the editor, click Copy script below, paste it in, and press Ctrl+S.

2 · Publish it

  1. Click Deploy (top-right) → New deployment.
  2. Click the gear next to "Select type" and choose Web app.
  3. Set Execute as: Me and Who has access: Anyone, then click Deploy.
  4. Click Authorize access and pick the company account. Google asks you to allow the script to access your Google Drive — it only reads folder names and IDs and never changes files. Because it is your own script, Google shows "Google hasn't verified this app": click Advanced → Go to 70mai Drive links (unsafe) → Allow.
  5. Copy the Web app URL (it ends in /exec).

3 · Tell the monitor about it

Paste the Web app URL here. This page checks that the script answers without a sign-in (the setting that matters most) and builds the monitor link:

  1. Open that monitor link once on the bench laptop (it is the usual monitor link with ?gdrive=… added). The monitor asks "Use this Google Apps Script…?" — click OK. The laptop remembers it.
  2. The green note now reads 📨 Lark alerts armed · Drive links on (script …xxxxxxxx). Those eight characters are the end of your script's address — a quick way to see the right script is in use.
  3. If the laptop's link also carries ?larkkey= or ?cap=, keep them; they can all be in one link, joined with &.

What you get

  • Fault messages: Google Drive folder: https://drive.google.com/drive/folders/… — opens that unit's folder directly.
  • If a fault happens in the first minutes of the night, before Google Drive for desktop has uploaded the unit's folder, the message carries the script's own link instead. Opening it shows a small page with one button, Open in Google Drive, which goes to the folder once it exists.
  • The end-of-night message links the night folder the same way.

Good to know

  • Updating the script later (for example after it changes on this page): paste the new script over the old one, save, then Deploy → Manage deployments → ✎ (edit) → Version: New version → Deploy. The URL stays the same, so the laptops need nothing. A brand-new deployment would make a new URL.
  • If "Anyone" is not offered (company policy), choose Anyone within <your company>. The monitor then cannot ask the script directly, so fault messages always carry the script's link rather than the direct one; it still opens the folder for anyone signed into the company account.
  • Narrower permission (optional): by default Google asks for full Drive access even though the script only reads. To ask for read-only instead, in the script editor open Project Settings (gear), tick Show "appsscript.json" manifest file, open that file and add "oauthScopes": ["https://www.googleapis.com/auth/drive.readonly"] inside the braces, then deploy a new version and re-authorize.
  • To switch it off on a laptop, open the monitor once with ?gdrive=off.
  • The script never changes anything in Drive, and a folder ID on its own does not let anyone open the files — opening a folder still needs that person's own Drive access.
